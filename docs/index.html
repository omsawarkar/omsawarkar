Which pages should an editor review first?

A simple CTR baseline, a learned ranking, and what broader validation changed.

Abstract

Can a simple peer-gap score help an editor prioritize pages for investigation, and does logistic regression improve its ranking? This study uses the March 2026 warehouse partition containing 9,841,378 daily rows, with 6,531 eligible items from 21 clients in the later-outcome comparison. Early-March measurements define a transparent baseline and five model inputs, while late-March CTR defines a diagnostic outcome evaluated with client-grouped splits. Both methods achieved Precision@10 of 1.00 in pooled grouped evaluation, but the baseline exceeded the model on average precision (0.8566 versus 0.8025). The resulting historical playbook supports human investigation of below-peer CTR, without establishing that content updates improve traffic.

Decision: retain the transparent baseline. Broader validation did not establish a consistent model advantage for the review queue.

01 / The decision: which pages deserve a closer look?

An editor has time to inspect ten pages, not thousands. A poor recommendation wastes editorial effort; a missed issue delays a useful investigation. The output should therefore be an understandable review order, with reasons and a human decision before changes.

The initial lane concerned content-refresh opportunities. The implemented analysis narrows this to search click-through rate (CTR), because the daily table does not contain update history. It cannot diagnose staleness. The unit of recommendation is one pseudonymized client–content pair.

03 / Methodology: a baseline before a learned model

Baseline and signal checks

The early-window bucket comparisons showed lower pooled CTR in worse position groups: 0.778%, 0.702%, 0.547%, and 0.205% across positions 1–3, >3–10, >10–20, and >20. Higher-volume groups also had lower median CTR within each position group, opposite to the tested hypothesis. These descriptive checks motivated position-and-volume peers, not causal claims.

Position is impression-weighted across observed days, excluding nonpositive position values. Volume groups are 100–499, 500–1,999, and 2,000+ impressions. A peer group must contain at least 20 items. Each item contributes to its own group median.

Review score = impressions × max(peer median CTR − item CTR, 0)

All rates in this formula are fractions. The score is a peer-gap index, not recoverable clicks. Noneligible queue items receive zero; ties are resolved by impressions and stable identifier ordering.

Five inputs and one later-outcome proxy

The model inputs are early-window impressions, clicks, CTR, sessions, and engagement rate. CTR is total clicks / impressions; engagement rate is total engaged sessions / sessions. Undefined denominators remain missing. The pipeline applies training-only median imputation, log(1+x), standardization, and logistic regression (seed 42; maximum 2,000 iterations).

The binary outcome is 1 if CTR during 21–31 March is below the item’s frozen early-window peer median; otherwise it is 0. Evaluation requires ≥5 GSC-available outcome days and ≥100 outcome impressions. This is a later observed CTR proxy, distinct from Week 3’s click-decline diagnostic and from the original human-review objective.

Validation and leakage boundaries

The original GroupShuffleSplit held out six clients (246 items); five-fold GroupKFold subsequently produced out-of-fold predictions for all 6,531 items. Preprocessing is fitted inside each training split. IDs, peer benchmarks, baseline scores, product flags, and late measurements are excluded from the five model inputs.

The frozen benchmark includes held-out clients’ early observations. Thus this is a known-reference-population experiment, not fully inductive prediction for unseen clients. Outcome-coverage selection is retrospective. The original 246-item test set was already inspected, so the expanded evaluation is exploratory rather than a fresh untouched holdout.

04 / The original model advantage did not persist

Errors matter more than a perfect top-ten number

At threshold 0.5 there were 1,979 out-of-fold errors. Three confident false positives had zero early clicks from 2,061, 2,034, and 2,337 impressions. Their predicted probabilities were about 0.999, yet later CTR rose above the frozen benchmark. Zero early clicks did not guarantee persistent below-benchmark CTR. These are aggregate case descriptions, not identifiable pages.

On the original fit, clicks, impressions, and sessions had the largest absolute standardized coefficients. Clicks, impressions, and CTR are mathematically related, so individual coefficients do not provide causal explanations. We retain the baseline rather than claim a consistent model advantage.

05 / Limitations: what this evidence cannot establish

  • No intervention evidence. Later below-peer CTR is not a label for update benefit. No actual page reviews or content changes were performed.
  • Restricted population. Requiring GSC and GA4 availability, early coverage, and later coverage selects a small subset. Missing rows are not zero activity.
  • Shared reference information. Peer medians use all eligible early clients; broad buckets mix query, device, country, intent, and client differences.
  • Short windows and unequal histories. Observation-day totals, weekday composition, low click counts, and reporting latency can affect results. Seasonal or long-term generalization was not tested.
  • Exploratory validation. One large client dominates, pooled probabilities may differ in calibration, and no uncertainty intervals or significance tests were produced. Reusing already inspected March outcomes does not create a sealed test.
  • Proxy alignment. The label reuses an early benchmark, so apparent predictive ability may reflect persistence of relative CTR rather than actionable content defects. The original editorial Precision@10 remains unmeasured.

Review, approval, and cost

Verify measurements and peer suitability, inspect authorized page content, document the issue, and assign APPROVE_SPECIFIC_CHANGE, INVESTIGATE_FURTHER, MONITOR, or REJECT_RECOMMENDATION. A content owner approves implementation. Never automate publishing, deletion, redirects, or indexing changes from this score.

A proposed pilot reviews ten candidates at an initial 15 minutes each (150 minutes). This is a planning assumption, not a measured cost. Record actual time and confirmed actionable issues; the provisional goal of seven actionable cases out of ten is not an achieved result.

Monitoring and reconsideration

Check coverage and schema before each weekly refresh. Pause on duplicates, missing keys, invalid measurements, or an unexplained >20% relative change in eligible counts. Two pilot batches below the proposed seven-of-ten yield trigger investigation. Thresholds are provisional. For approved changes, inspect 30- and 60-day follow-up with comparable untreated pages where possible; a simple before/after change is not causal proof.

This baseline has no fitted model to retrain. Revisit rules through a documented validation process. Reconsider ML only when independent labels and repeated comparisons establish useful gains.

07 / Reproducibility and evidence trail

The figures and tables on this page are rebuilt from the saved executed outputs in the uploaded repository, not a new authenticated warehouse run. Source hashes and extracted metrics are recorded in paper_metrics.json.

  1. Clone the repository and install huggingface_hub duckdb pandas numpy scikit-learn matplotlib.

  3. Run the data-contract, baseline, model, validation, and playbook notebooks in order, top to bottom. Raw queue CSVs remain outside GitHub.
  4. Run python work/scripts/build_research_paper.py from the repository root, or run the capstone notebook, to rebuild this page from executed outputs.

Seeds are 42 where randomization is used. The Week 5 output records scikit-learn 1.6.1; other analysis packages were installed without full version pins, so a bit-for-bit training environment was not captured. The report build has no gated-data dependency. Public artifact links follow.
